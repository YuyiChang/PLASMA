PLASMA

Platform for LSL-based Acquisition of Sensor Metrics and Analytics — run a multi-device study session from one window: initialise every sensor, stream it over Lab Streaming Layer, and record the whole room to a single XDF file.

What it does

One window for the whole session

PLASMA opens in your browser as a set of tabs. Each one covers a stage of a recording session, from selecting devices to checking the streams while they run. Every device is a plugin, so the tab list reflects whatever you enabled.

Session Dashboard

Initialise and run

Enter subject and session IDs, pick the devices for this run, initialise them in one click, then Start / Stop collection. A live panel shows per-device status as it changes.

Data Dashboard

Watch the streams

See every LSL stream on the session — PLASMA's own outlets and anything else on the network — so you can confirm data is flowing before you trust the recording.

Configuration

Catalog and credentials

Toggle devices in the catalog, edit MSense name ↔ address pairs, set LiDAR / eye-tracker IP addresses, and import or export the whole config as JSON.

🍠 YAMS (MSense Tools)

Wristband workflow

Contributed by the MSense plugin: run signal-quality checks, download onboard sessions, extract raw .bin to CSV, and reconcile device clocks.

LSL → XDF recorder

Record everything

A built-in recorder captures the session's streams to a standard XDF file, with a capacity indicator so you know it is keeping up.

Session memo

Know the room at a glance

An HTML memo panel colour-codes every device and recording by state — collecting, ready, disconnected, stalled, error — the whole session on one screen.

Device support

Seven integrations, one clock

Each sensor ships as a plugin and streams over LSL (Lab Streaming Layer), so every channel lands in the recording time-stamped against the same session clock. Enable only the ones a study needs.

Install

Three ways to get it

If you just want to run PLASMA, take the first one — it needs no Python at all.

Prebuilt app

A single executable, built in CI for all three platforms. No Python, no dependencies — download and run.

PLASMA_MacOS_arm64, PLASMA_Linux_x64, or PLASMA_Windows_x64.exe, attached to each release.

Download the latest release →

From source

For development, or to run unreleased changes.

conda create -n plasma python=3.12
conda activate plasma
pip install -e ".[all]"
python -m plasma

A lean subset works too: ".[msense]", ".[qb2,pupil]".

From another project

The distribution is plasma-app; the import package is plasma.

pip install "plasma-app[msense] @ git+https://github.com/YuyiChang/PLASMA@v2.0.0"

Extras map to plugins: msense, qb2, pupil, shimmer, obs, all.

Don't skip liblsl. The Lab Streaming Layer library is a native dependency that pip cannot supply on every platform. Install it from conda-forge (conda install -c conda-forge liblsl) — it is the step most source installs miss, and without it the app fails at startup.

However you install it, PLASMA starts a local server and opens your browser at http://127.0.0.1:7860. Nothing leaves your machine. Writable state (device config, calibration, data/ recordings, the session log) goes to $PLASMA_HOME if set, otherwise a per-OS app-data directory for the packaged app, otherwise the working directory when run from source.

Usage

The arc of a session

The normal path from an empty room to a finished recording, in four steps.

  1. Configure

    In Configuration, enable the devices this study uses and fill in their addresses — MSense name ↔ UUID/MAC pairs, the LiDAR and eye-tracker IPs. Click Apply, then Refresh list in the dashboard. Export the config to reuse it on another machine.

  2. Initialise

    In Session Dashboard, enter the subject and session IDs (they are encoded into the output names automatically), select the devices for this run, and initialise. Each device connects and announces its LSL streams.

  3. Record

    Start collection. The built-in recorder writes every session stream to one XDF file; the memo panel and the Data Dashboard show, live, that each device is producing data. Stop when the session ends.

  4. Review

    Check the memo for any device that ended in a warning or error state, then open the XDF in your analysis tool. MSense onboard data can be pulled and extracted to CSV from the YAMS tab.

Recording & sync

One XDF, honestly time-stamped

PLASMA records through Lab Streaming Layer so device streams share a clock, and it tags its own outlets so the recorder can tell them apart from everything else on the network.

Built-in LSL → XDF recorder

Captures the session's streams to a standard XDF file with a capacity indicator. No separate LabRecorder process to babysit.

Origin tagging

Every outlet PLASMA creates is marked at construction, so the recorder — and you — can distinguish PLASMA's streams from a stray lab tool or a concurrent test run.

Known limitation. The recorder currently captures every stream on the default liblsl session, so a concurrent pytest run or another lab tool can leak into a recording, and re-Initialize does not fully tear down old outlets. Direction — SessionID scoping, outlet lifecycle — is in LSL lifecycle & scoping.
